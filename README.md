# Отчёт по лабораторной работе № 3

## 1. Цель работы

Научиться запускать контейнеры с заданными именами и портами, связывать контейнеры, описывать стек из двух сервисов в Docker Compose, масштабировать приложение и корректно завершать работу стека.

## 2. Среда выполнения

Работа выполнялась в Windows с использованием PowerShell и Docker Desktop.

| Компонент | Версия / значение |
|---|---|
| Docker Desktop | 4.96.0 |
| Docker Engine | 29.9.1 |
| Docker Compose | v5.6.0 |
| Docker OS type | `linux` |
| Docker context | `desktop-linux` |
| Рабочий каталог | `C:\Users\Admin\rocketcounter` |

Среда проверялась командами:

```powershell
docker version
docker compose version
docker info --format '{{.OSType}}'
docker ps
```

Команда `docker info --format '{{.OSType}}'` вернула `linux`, что соответствует использованию Linux-контейнеров.

## 3. Ход выполнения работы

### 3.1. Часть 1 — запуск контейнеров вручную

Сначала был загружен образ Redis и создан контейнер с требуемым именем:

```powershell
docker pull redis
docker run -d --name redis redis
```

Затем был загружен образ приложения и запущен контейнер Rocket Counter:

```powershell
docker pull rotorocloud/rocket-counter
docker run -d --name rocketcounter --link redis:redis -p 8085:5000 rotorocloud/rocket-counter
```

Параметр `--link redis:redis` использован для связи приложения с Redis, как указано в первой части задания. Docker вывел предупреждение о deprecated links; это предупреждение, а не ошибка запуска.

По предоставленному выводу `docker ps` оба контейнера имели статус `Up`. Для `rocketcounter` была опубликована пара портов `8085:5000` (IPv4 и IPv6):

```text
CONTAINER ID   IMAGE                        COMMAND        STATUS       PORTS                                         NAMES
4ecf6869df96   rotorocloud/rocket-counter   "flask run"    Up 4 minutes 0.0.0.0:8085->5000/tcp, [::]:8085->5000/tcp   rocketcounter
6b1cb37c5bf2   redis                        ...            Up 48 minutes 6379/tcp                                      redis
```

Работа веб-интерфейса подтверждается собственным скриншотом страницы с ракетой и числовым значением счётчика.

### 3.2. Часть 2 — запуск сервисов через Docker Compose

Для запуска стека был использован файл `docker-compose.yml` с двумя сервисами: `redis` и `rocketcounter`. На этапе первичной проверки по условию задания публикация порта приложения должна иметь вид `8085:5000`.

Команда запуска:

```powershell
docker compose up -d
```

В журнале PowerShell зафиксировано создание сети проекта и запуск обоих сервисов:

```text
[+] up 3/3
Network rocketcounter_default           Created
Container rocketcounter-redis-1         Started
Container rocketcounter-rocketcounter-1 Started
```

В Compose не используется `links`: сервисы подключены к общей сети проекта, а Redis доступен приложению по имени сервиса `redis`.

### 3.3. Часть 3 — масштабирование приложения

Для запуска двух экземпляров приложения фиксированная публикация `8085:5000` заменяется на динамическую:

```yaml
ports:
  - "0:5000"
```

Команда масштабирования:

```powershell
docker compose up -d --scale rocketcounter=2
```

В журнале PowerShell присутствует успешный результат `up 4/4`, в котором отмечены один контейнер Redis и две реплики приложения:

```text
[+] up 4/4
Network rocketcounter_default            Created
Container rocketcounter-redis-1          Started
Container rocketcounter-rocketcounter-2  Started
Container rocketcounter-rocketcounter-1  Started
```

Фактические host-порты реплик необходимо получить контрольными командами:

```powershell
docker compose ps
docker compose port --index=1 rocketcounter 5000
docker compose port --index=2 rocketcounter 5000
```

После получения портов необходимо открыть оба адреса в браузере, нажать кнопку в первом окне, обновить второе и проверить, что обе реплики показывают общее состояние счётчика, хранящееся в одном Redis. (Скриншоты не сохранились)

### 3.4. Часть 4 — завершение работы и очистка

Для удаления Compose-стека выполнялась команда:

```powershell
docker compose down -v
```

В журнале виден успешный результат удаления двух реплик приложения, контейнера Redis и сети `rocketcounter_default`.

Ручные контейнеры дополнительно останавливались командами:

```powershell
docker stop redis
docker stop rocketcounter
docker rm -f redis
docker rm -f rocketcounter
```

Эти команды останавливают и удаляют контейнеры

Для подтверждения очистки имеется скриншот Docker Desktop с пустым списком контейнеров

## 4. Ответы на контрольные вопросы

### 1. Зачем в первой части использовался `--link` и почему в Compose он не нужен?

В первой части контейнеры запускались отдельно. Параметр `--link redis:redis` связывает приложение с контейнером Redis и позволяет обращаться к нему по имени `redis`. В Docker Compose сервисы автоматически подключаются к общей сети проекта, а встроенный DNS Docker разрешает имена сервисов. Поэтому отдельная директива `links` не требуется. В лабораторной `--link` используется намеренно для знакомства с устаревшим способом связи контейнеров.

### 2. Чем отличается `image` от `build` в Compose?

`image` указывает готовый образ, из которого создаётся контейнер. `build` задаёт параметры сборки нового образа на основе Dockerfile и контекста сборки. В данной работе используется опубликованный образ `rotorocloud/rocket-counter`, поэтому применяется `image`.

### 3. Почему нельзя масштабировать сервис с публикацией фиксированного порта на одном хосте? Перечислите способы обойти это ограничение.

На одном хосте несколько реплик не могут одновременно занять один и тот же порт хоста, например `8085`. Обойти ограничение можно назначением разных портов, динамическим назначением портов, использованием reverse proxy или балансировщика нагрузки, либо размещением экземпляров на разных хостах или IP-адресах.

### 4. Что делает `docker compose down -v` и чем отличается от `down` без `-v`?

`docker compose down` останавливает и удаляет контейнеры проекта и созданную сеть. Параметр `-v` дополнительно удаляет связанные с проектом именованные и анонимные тома. Таким образом, `down -v` выполняет более полную очистку ресурсов и связанных с ними данных.

### 5. Как в Compose обеспечивается сетевое имя сервиса для обращения из другого сервиса?

Compose создаёт общую сеть проекта и подключает к ней сервисы. Встроенный DNS Docker разрешает имена сервисов в этой сети. Поэтому приложение может обратиться к Redis по имени `redis` и стандартному порту Redis `6379`.
